# script-writer — 一句话 → 实体分析 + 镜头扩写

## 这个 skill 做什么

用户只给一句创意（通常是一个镜头 / 一个场景），本 skill 不写长剧，只做一件事：
**把这句话扩写成能让视频生成模型「拍得出来」的分镜描述**。

核心手段是「实体优先」：先数清楚画面里有多少个会动的实体，逐个写清它长什么样、怎么动，
再把动作按时间切成「镜头1 / 镜头2 / 镜头3」。

## 输入

一句话，例如：

- `一只猫和宇航员在月球上玩球`
- `一个机器人撑着伞在雨中追一只气球`
- `小女孩在雪地里堆雪人，雪人突然活了`

风格 / 质感等偏好若已写在句子里（如「治愈系」「写实」）就直接采用；没有就合理推断。
**不要**追问平台、时长等旧短剧参数。

## 处理流程（务必按序）

### 第 1 步：实体分析 —— 最关键的一步

1. 从一句话里找出所有需要被单独描述的对象。判断标准：
   - 能在画面里**独立运动**、或需要被镜头**单独跟踪**的东西，是实体；
   - 把它从画面里拿走，动作链就断了的，也是实体；
   - 背景 / 氛围元素（天空、地面、尘埃、光效、围观人群等）**不算**实体，除非它本身是动作的主体。

2. 显式数清并列出：`共 N 个实体：A、B、C…`

3. 为每个实体写清两件事：
   - **appearance（静态外观）**：长什么样、穿什么、什么颜色 / 材质、面部 / 姿态特征。
   - **motion（动态动作）**：它在这段里具体怎么动 —— 用可被镜头拍出来的动词（跳、弹、抱、推、漂浮、溅起、滑、追），**不要用抽象词**。

4. 动作可视化（硬性要求）：抽象情绪 / 状态必须转成具体身体行为或物理运动。
   - 「开心」→「保持开心的微笑」
   - 「用力」→「轻微用力推出」
   - 「突然活了」→「雪人抖落积雪、抬起手臂」
   - 视频模型拍不出「开心」，只能拍出「微笑」。

5. 自检：如果某个实体的 motion 含糊，最终视频必然偏离想法。**每个实体都要把 motion 写透。**

### 第 2 步：整体设定 + 镜头分镜

1. 写一句「整体设定」：场景 + 风格 + 质感 + 氛围（例：`月球表面治愈系轻科幻场景，写实太空质感`）。
2. 把动作按时间顺序切成「镜头1、镜头2、镜头3…」（一般 2~4 个镜头），每个镜头：
   - 写清画面内容（谁在什么位置、什么状态、什么构图 / 景别）；
   - 把该镜头里出现的实体的 motion 写进去；
   - 一个镜头至少要有一个实体的动作。

### 第 3 步：写出三份文件

按下方 schema 用 Write 工具写出三份文件到 `output/projects/<safe_title>/` 下，
`<safe_title>` 由标题 sanitize 而来（去空格与非法字符，如 `月球玩球的猫`）。
三份文件描述的是**同一批实体、同一组分镜**，务必保持一致。

## 输出文件

### 1) `instances_prompt.yaml` — 多实例描述（实体清单）

```yaml
instances:
  - id: 主体1          # 稳定代号，供镜头里引用；按序编号
    name: 猫           # 实体名（从一句话提取的词）
    appearance: ...    # 静态外观
    motion: ...        # 动态动作（本 skill 的核心输出）
  - id: 主体2
    name: 宇航员
    appearance: ...
    motion: ...
```

### 2) `script.yaml` — 供视频生成接口拼接提示词

```yaml
script:
  title: 月球玩球的猫
  overall_setting: 月球表面治愈系轻科幻场景，写实太空质感
  instances:          # 与 instances_prompt.yaml 完全一致
    - id: 主体1
      name: 猫
      appearance: ...
      motion: ...
    # ...
  shots:
    - id: 1
      description: 全景太空，蓝色地球悬浮于画面右上方，灰色月面占据下方三分之二，一个玩具足球在月面弹跳，溅起放射状尘埃
      entities: [主体3]          # 本镜头涉及的实体 id（引用 instances[].id）
    - id: 2
      description: 皮球随后弹起回到宇航员手中，宇航员保持开心微笑，轻微用力推出球
      entities: [主体2, 主体3]
```

### 3) `script.md` — 给你自己阅读

人类可读的 Markdown 版：整体设定 + 实体清单（每个实体的外观 / 动作一句话）+ 分镜列表。

### script.md

```markdown
# 月球玩球的猫

## 整体设定
月球表面治愈系轻科幻场景，写实太空质感。

## 实体（3 个）
1. 猫：身着宇航服的布偶猫，白色长绒毛，圆脸蓝眼 → 高高跃起，四只爪子抱住球，未落地反而在地面上方漂浮
2. 宇航员：穿白色宇航服、透明面罩的人类，面带开心微笑 → 接住弹回的球，保持微笑，轻微用力推出球
3. 球：一个玩具足球 → 在月面弹跳，溅起放射状尘埃，随后弹回宇航员手中

## 分镜
- 镜头1：全景太空，蓝色地球悬浮于画面右上方，灰色月面占据下方三分之二，一个玩具足球在月面弹跳，溅起放射状尘埃。
- 镜头2：皮球随后弹起回到宇航员手中，宇航员保持开心微笑，轻微用力推出球。
- 镜头3：身着宇航服的布偶猫此时高高跃起，四只爪子抱住球，结果没有落地，反而在地面上方漂浮了起来。
```

## 写作铁律

1. **实体优先**：先列实体、写透每个实体的 motion，再切分镜。反过来做（先写镜头再想实体）会漏实体。
2. **动作可视化**：禁止抽象情绪词，一律转成身体行为 / 物理运动。
3. **实体数量要数对**：每份文件开头都显式写 `共 N 个实体`。
4. **一个镜头 ≥ 一个实体动作**：镜头不能只是空景或静态描述。
5. **三份文件一致**：同一批实体、同一组分镜，只是呈现形式不同。

## 注意事项

- 这是纯提示词 skill：直接用 Write 工具写文件，**不调 DeepSeek API、不跑任何 Python**。
- YAML 必须合法（可被 `yaml.safe_load` 解析）；写文件用 UTF-8。
- `instances_prompt.yaml` 是图片 agent（`agents/image/generator.py`）的直接输入；`script.yaml` 的 `shots[]`（`description` + `entities`）是视频生成（`agents/video/generate.py`）的输入。
